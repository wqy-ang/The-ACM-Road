# 哈希 trick：EPS.AC 题解笔记
> 题目核心：3个人各自给出题目的难度排列，分割点需要**至少两个人都认可这个分割**。求最多划分段数。
> 原题：EPS.AC
## 题意浓缩
有 $n$ 道题，3个排列 $p_0,p_1,p_2$。
我们从左往右切分，每一刀（分割线）满足：至少两个人认为，**刀左边所有题，在他自己的排列里全部出现在刀右边所有题前面**。
求最多能切出多少段。
> 关键观察：
> 对一个人来说，什么时候支持在位置 $i$（前 $i$ 个元素）切一刀？
> 设 `pos[x]` 为题 $x$ 在这个人序列里的下标。
> 前 $i$ 道题的**最大 pos 值** = $i-1$。
> 也就是：前 $i$ 个元素刚好是这个人排列里前 $i$ 道题。
> ✅ 此时这个人支持这个分割点。
举例：
人的排列：`3,1,2,4`
pos[3]=0, pos[1]=1, pos[2]=2, pos[4]=3
取前2题：`3,1`，max(pos)=1，刚好等于 $2-1$，这个人支持在i=2切一刀。
取前3题：`3,1,2`，max(pos)=2，支持i=3。

> 分割点下标约定：
> $k$ 代表前缀长度为 $k$（切在第 $k$ 题之后），$1\le k \le n-1$；$k=n$ 是末尾，不算分割。

## 做法一：确定性 O(n) 标记法（无哈希，无冲突）
### 核心原理
两个人A、B同时认可分割点 $k$，等价于：**长度为k的前缀集合，既是A的前k个元素集合，同时也是B的前k个元素集合**。

对于一对排列 $(a,b)$：
1. 先记录每个元素在 $b$ 中的位置 `pos[x]`
2. 遍历 $a$，维护已经遍历过元素在 $b$ 中的位置的最大值 `max_pos`
3. 遍历到第 $i$ 项（0下标），对应前缀长度 $i+1$；若 `max_pos == i`，说明这个前缀集合正好等于 $b$ 的前 $i+1$ 个元素集合。
4. 此时 $k=i+1$ 是A、B共同合法分割点，标记 `valid[k]=true`。

三对组合：$(p1,p2),(p2,p3),(p1,p3)$，全部跑一遍标记；只要被任意一对标记为true，该分割点就合法（满足至少两人认可）。
最终段数 = 合法分割点数量 $+1$。

> 时间复杂度：每一对O(n)，三对总 $O(3n)=O(n)$；完全确定，不存在哈希冲突风险。

```cpp
// valid[i]：前缀长度i是否为合法分割点（切在i题之后）
vector<bool> valid(n, false);

auto mark = [&](const vector<int>& a, const vector<int>& b) {
    vector<int> pos(n + 1);
    for (int i = 0; i < n; ++i) {
        pos[b[i]] = i; // b中每个数的下标
    }
    int max_pos = -1;
    for (int i = 0; i < n; ++i) {
        max_pos = max(max_pos, pos[a[i]]);
        // i是0下标，前缀长度=i+1；max_pos == i：集合完全匹配
        if (max_pos == i && i + 1 < n) {
            valid[i + 1] = true;
        }
    }
};

mark(p1,p2); mark(p2,p3); mark(p1,p3);

int cnt = 0;
for(int k=1;k<n;k++) if(valid[k]) cnt++;
int ans = cnt + 1;
```

### 理解关键点
- 为什么 `max_pos == i` 代表集合相等：
遍历a的前 $i+1$ 个元素，把它们映射到b里面的下标；如果这些下标的最大值恰好等于 $i$，说明这 $i+1$ 个数恰好填满b下标 $0\dots i$，不多不少，集合完全一致。
- `i+1 < n`：不能在n的位置切，末尾不算分割。
- valid数组是bool，只要任意一对排列认定该位置合法就置为true，实现“至少两人同意”。

AC参考代码：
```cpp
void solve() {
    int n;
    cin >> n;
    
    vector<int> p1(n), p2(n), p3(n);
    for (int i = 0; i < n; ++i) cin >> p1[i];
    for (int i = 0; i < n; ++i) cin >> p2[i];
    for (int i = 0; i < n; ++i) cin >> p3[i];
    
    // valid[i] 表示第 i 个位置后能否作为一条合法分界线 (即前 i 道题为第一档)
    // 分界线位置 k 的范围是 1 到 n-1
    vector<bool> valid(n, false);
    
    // 辅助函数：检查排列 a 和排列 b，标记它们共同的前缀集合分界线
    auto mark = [&](const vector<int>& a, const vector<int>& b) {
        vector<int> pos(n + 1);
        for (int i = 0; i < n; ++i) {
            pos[b[i]] = i; // 记录 b 中每个数字的位置
        }
        int max_pos = -1;
        for (int i = 0; i < n; ++i) {
            max_pos = max(max_pos, pos[a[i]]);
            // 如果前 i+1 个数字在 b 中的最大位置刚好是 i，说明集合相同
            // 此时 i+1 可以作为分界线（前提是 i+1 < n）
            if (max_pos == i && i + 1 < n) {
                valid[i + 1] = true;
            }
        }
    };
    
    // 检查三对排列
    mark(p1, p2);
    mark(p2, p3);
    mark(p1, p3);
    
    int boundary_cnt = 0;
    for (int i = 1; i < n; ++i) {
        if (valid[i]) {
            boundary_cnt++;
        }
    }
    
    // 档次数量 = 合法分界线数量 + 1
    cout << boundary_cnt + 1 << "\n";
}
```

## （EPS.AC 题个人理解）
> 背景：$a,b$ 都是 $n$ 的排列。
> $a$ 数组可以看作是 $b$ 数组的打乱。
> 不失一般性，做变换：把 $b$ 当作 $1,2,3,\dots,n$ 的标准排列；$a$ 是另一个排列。
>
> 例：
> $b:1,2,3,4,\dots,n$
> $a:4,2,1,3,\dots$

命题：
若 $a$ 与 $b$ 的**前缀集合相同**。设前缀集合大小为 $i$，集合内包含 $1\sim i$，那么 $a$ 的前缀集合中的最大值应为 $i$。

简单证明：
一个集合大小为 $k$，内部数字互不相同，且最大值为 $k$，则这个集合恰好就是 $\{1,2,\dots,k\}$。

## 个人推导理解（对应题目核心 trick）
1. 把 $b$ 标准化为 $1,2,\dots,n$，$b$ 中数字 $x$ 的位置就是 $pos_b[x]=x-1$。
2. 取 $a$ 的前 $i$ 个元素构成集合 $S$。
   - $|S|=i$；
   - 如果集合 $S$ 在 $b$ 里的位置的最大值等于 $i-1$；
   - 等价于：集合 $S$ 的最大值是 $i$；
   - 根据上面命题：$S=\{1,2,\dots,i\}$，也就是 $a,b$ 的长度为 $i$ 的前缀集合完全一样。

> 这就是代码里 `max_pos == i` 判断的底层逻辑！

### 命题严格证明
> 已知：集合 $S$，元素都是正整数，互不相同，$|S|=k$，$\max(S)=k$。
> 求证：$S=\{1,2,\dots,k\}$。

证明：
集合有 $k$ 个互不相同的正整数，最大是 $k$。
正整数不超过 $k$ 的一共只有 $k$ 个：$1,2,\dots,k$。
集合刚好填满全部 $k$ 个数，没有多余，没有缺失。
$\Rightarrow S=\{1,2,\dots,k\}$。

### 映射回原题
当 $b$ 不是标准排列时，做坐标映射：
对每个数字 $x$，记 $pos_b[x]$ = $x$ 在排列 $b$ 中的下标。
我们遍历 $a$ 的前若干项，维护 `max_pos = max{ pos_b[x] | x 是a已遍历元素 }`。
- 遍历到 $a$ 的第 $i+1$ 个元素（0下标 $i$），`max_pos == i`
- 含义：这 $i+1$ 个元素映射到 $b$ 的下标集合，大小 $i+1$，最大值等于 $i$。
- 套用命题：下标集合就是 $\{0,1,\dots,i\}$。
- 说明：$a$ 的前 $i+1$ 个元素，恰好就是 $b$ 的前 $i+1$ 个元素。
- 也就是：**两者前缀集合相等**，这一刀分割点两个人都认可。

## 做法二：哈希思路（集合哈希，你代码的思路）
> 思路：给每个题 $x$ 分配一个唯一随机哈希值 $h[x]$。
> 一个人，前 $i$ 项的哈希和，**当且仅当这前 $i$ 个元素正好是他排列的前 $i$ 个元素时**，哈希和等于他自己前 $i$ 项的哈希前缀和。
> 本质：**集合哈希**。前缀集合相同 ⇨ 两个人都认为当前前缀正好是自己排列前i题 ⇨ 支持分割。

你代码的做法：
1. 预先给每个题号 $i$ 分配 `hash[i]`（幂次）。
2. 遍历第0个人的序列，累加 `a += f[0][i] * hash[f[0][i]]`。
3. 同理累加b、c。
4. 如果 `a==b || a==c || b==c`：说明至少两个人，当前前缀集合完全相同，也就是两人都支持这个分割点，计数+1。

### 代码可能出现的问题
1. **哈希冲突风险**：单模数多项式哈希有概率撞hash。竞赛标准做法是双哈希（两个mod，一对hash值）。
2. 哈希基数设计：`hash[i]=131^i`，这里用 `x * hash[x]` 其实不是标准集合哈希；集合哈希一般直接对元素随机赋值，前缀求和。
3. 数据类型：`int long long` 没问题，但乘法取模注意溢出（C++ long long 乘的时候可能爆）。
4. 边界：$i$ 从0到n-1，对应前缀长度 $i+1$；循环内每一轮判断等价于前缀 $i+1$；当 $i+1=n$（最后一轮）也会进入if判断，会错误把末尾算作分割。**原代码存在边界bug！**
> ⚠️原哈希代码bug：循环i取到n‑1，此时前缀长度等于n（全部元素），`a==b||a==c||b==c` 一定成立，cnt会多算一刀。要限制只有 `i+1 < n` 才计数。

原代码：
```cpp
const int mod=1e9+7;
void solve() {
    int n;
    cin>>n;
    vector<vector<int>>f(3,vector<int>(n));
    for(int i=0;i<3;i++){
        for(int j=0;j<n;j++){
            cin>>f[i][j];
        }
    }
    vector<int>hash(n+1);
    int h=1;
    for(int i=1;i<=n;i++){
        hash[i]=h;
        h=h*131%mod;
    }
    
    int a=0, b=0, c=0;
    int cnt = 0;
    for(int i=0; i<n; i++) {
        a=(a+f[0][i]*hash[f[0][i]])%mod;
        b=(b+f[1][i]*hash[f[1][i]])%mod;
        c=(c+f[2][i]*hash[f[2][i]])%mod;
        if(a==b || a==c || b==c) cnt++;
    }
    cout << cnt << '\n';
}
```
